### 批任务与设计（2026-11-11 主 agent）

**需求四条**（用户 2026-11-11 原话）：①观察者仅可查看看板、项目列表两个页面 ②看板「导出 Excel」对观察者不显示 ③项目列表「新建项目、导入、导出」对观察者不显示 ④观察者无编辑权限，全部数据只读。

**现状勘察**（xxwei 账号实测「所有都能看得到」的根因）：角色数据正确（PG user_account 表实证 xxwei=viewer），差距全在前端拦截——改造前 viewer 可见全部菜单项、/resources 路由放行、导出/导入按钮无角色判断、行内编辑/删除无判断；唯一既有守卫是「新建项目」按钮。后端写操作 viewer 本就 403（check_project_access/phase_access），但 /api/export/excel 仅要求登录。

**设计决策**：
- 菜单层：App.tsx navItems 增 viewer 分支——只留 dashboard/projects 两项（对齐 reporter 过滤先例）
- 路由层：/report、/resources 对 viewer 重定向「/」（/special-projects、/admin-center、/my-tasks 原有守卫已覆盖）；项目详情页 /projects/:id 保留可进（列表下钻入口，PhaseEditor 已有 readonly={userRole==='viewer'}）
- 按钮层：看板导出 Excel + 触发采集（状态变更动作归需求 4）、项目列表导入/导出、项目列表行内编辑/删除（columns.tsx 操作列 viewer 整列不渲染）、详情页页头编辑按钮——全部对 viewer 隐藏
- 接口层：/api/export/excel 对 viewer 403（按钮隐藏之外同步封禁，防止直接敲 URL 绕过）
- 角色来源：DashboardPage 沿用各页自取 getMe() 模式（与 ProjectListPage 一致），取失败按 viewer 保守处理（按钮隐藏）
- 文档同步：docs/PHASE5_PLAN.md 权限矩阵两处（角色表第 18 行、路由守卫表——原「viewer → 看板/项目(只读)/资源(只读)」为旧口径，本批收紧后资源负载不再对 viewer 开放）

**默认裁定四条**（方案确认时提出，用户以「继续」放行）：①项目详情页保留 viewer 只读可进 ②收藏星标保留（个人视图偏好非数据编辑）③看板「触发采集」对 viewer 隐藏 ④后端导出接口对 viewer 同步 403。

**验证门**：tsc --noEmit + npm run build 双门、pytest 全量回归（既有 viewer 语义不得破坏：health 200 / report 只读 / 专项 403 / 效率 403 / by-code 403）。

**调研留痕**：最贴近先例 = App.tsx reporter 菜单过滤与路由隔离（2026-10-29 权限分级需求 1，同款「菜单+路由」双层拦截）——本批 viewer 分层沿用其形状；columns.tsx 操作列裁剪无同款先例，用条件展开（列级隐藏优于按钮级，版面不留空壳操作列）。
