# 批次记录：填报页角标刷新体验（2026-11-04）

- **来源**：用户 2026-11-04 体验反馈——「我的申请和待我审批的角标显示的不够及时，刷新消除提示体感也不够明显」。
- **前情**：承接 `docs/batches/二期通知与作废下沉-2026-11-04.md`。
- **状态**：已收口 2026-11-04（本地验证 → 生产部署 → 冒烟 → GitHub）。

## §1 讨论与结论

- 根因不是「轮询太慢」一处：**「待我审批」的角标由该标签页自己 `load()` 后回填**——不点进去永远显示 0；顶部铃铛另有一套 60 秒轮询；两者时机不同，用户看到的就是「数字不对、也不及时」。
- 消除反馈弱同样有两层：角标归零是静默的（没有 toast、没有时间戳），刷新按钮点了没有任何视觉变化。

## §2 批次任务与设计

- **一个数据源**：新增 `GET /api/report/badges`，一次返回 `approvals`（待我审批）/ `mine`（我在审的申请）/ `notifications`（未读）三个计数；口径与既有列表端点完全一致（admin 看全部、普通用户按 managed_by + owner 文本回退）。
- **一个刷新节奏**：前端 `useReportBadges` —— 15 秒轮询（仅页面可见时）+ 窗口聚焦/切回标签页立即重拉 + 并发去重；业务动作（提交、审批、驳回、作废、切标签、点刷新）后立即重拉。
- **角标归属**：「我的申请」新增橙色角标 = 我在审的申请数；「待我审批」改用同一数据源，删除 `onCountChange` 回填链（少一条会漂移的数据链）。
- **消除反馈**：刷新按钮加 loading 旋钮 + 禁用态，右上角显示「更新于 HH:mm:ss」；「全部已读」补 `message.success` 提示。
