### 任务二：健康度评分（8-2 主体）

#### 后端（唯一口径来源）

**新文件 `backend/app/services/health_score.py`**：

```python
def calculate_health_score(project, phases, conflicts, today) -> HealthScore
```

- 输入：项目行、该项目的阶段列表、涉及该项目的冲突对列表（复用 detect_conflicts 结果过滤）、today。
- 输出 HealthScore（pydantic）：total + 五维明细（每维 score / weight / applicable / note / deduction 明细）+ 分档（green/yellow/red）。

五维计算（PHASE8_PLAN §2.2 权重，逐字落地）：
1. **进度达成 35**：机会分 = 35 × (实际进度% ÷ 应达进度%)，封顶 35；应达进度 = (today − plan_start) ÷ (plan_end − plan_start)；未开始或日期缺失 → 该维 applicable=False，标注「无计划基线」。
2. **延期暴露 25**：无延期阶段 25；有延期 max(0, 25 − 延期阶段数×5 − 最长延期天数÷2)。
3. **返工频次 15**：15 − 返工次数×5（下限 0）；返工 = Phase.rework_count > 0 累计。
4. **资源冲突 15**：15 − 参与冲突对数×5（下限 0）；冲突对复用 detect_conflicts（口径与看板/热力图同源）。
5. **计划合理性 10**：工期 ∈ [7,120] 天得 10；<7 或 >120 得 0 并标注「工期异常」；日期缺失 → applicable=False。

分档：总分 ≥80 绿 / 60–79 黄 / <60 红。**缺数据维不计入分母**（总分 = 可算维度得分之和，分母 = 可算维度权重之和），明细显式标注「无计划基线，仅按可算维度计分」——不用 0 冒充。

**搁置项目**：搁置项目健康度列显示「—」（不评），明细弹窗不展示。已完成项目正常评分（快照语义）。

#### 后端接口

`GET /api/projects/{id}/health`（单项目详情/弹窗用）+ 列表批量随行：`list_projects` 的 ProjectRead 扩展 `health` 可选字段（None = 不评）——避免 N+1（一次循环逐项目算，阶段/冲突数据已在内存）。看板「风险项目 N 个」卡：`GET /api/dashboard/stats` 扩展 `risk_projects`（分数升序列表，复用同一函数）。

#### 前端

1. **列表列**（拆分后 ProjectListPage）：「健康度」列（色点 + 分数），hover 弹出五维明细；搁置项目显「—」。
2. **详情页**（ProjectDetailPage 266 行，加 ~80 行）：标题行右侧总分色块 + 五维条形明细（Popover）。
3. **看板卡**（DashboardPage）：新增「风险项目 N 个」卡（第 7 卡，两行布局调整），点开分数升序列表弹窗（复用风险弹窗模式）。
4. **明细可解释**：每维展示「得分/权重/扣分原因」；缺数据维显示「不计分：无计划基线」。
5. **固定文案**：健康度弹窗底部「本分数为项目状态参考，不构成绩效考核」——考核防火墙（PHASE8_PLAN §7 风险表）。

### 关键决策（本批裁定记录）

1. **健康度随 list_projects 返回**（非独立批量端点）：列表已有一次全量查询，评分在响应组装循环内完成，避免第二请求与 N+1；单项目端点仅供详情弹窗刷新。
2. **搁置项目不评**：搁置 = 暂停评估语义，评「红」反而误导；列显示「—」。
3. **看板第 7 卡布局**：现 6 卡两行×3，加第 7 卡改两行×4 或 3+4？——**保持两行×3 不动，风险项目卡放「今日聚焦」区域上方独立一行**，避免挤压现有等高布局（用户 2026-11-05 刚裁定 6 卡等高）。
4. **冲突口径复用**：健康度的冲突计数 = detect_conflicts 结果中涉及该项目的冲突对数（含跨资源去重后行级），与今日风险队列 conflict 行口径一致；实现时按 (phase_a, phase_b) 对去重。
