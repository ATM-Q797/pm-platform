### 任务二：健康度评分（8-2 主体）

#### 后端（唯一口径来源）

**新文件 `backend/app/services/health_score.py`**：

```python
def calculate_health_score(project, phases, conflicts, today) -> HealthScore
```

- 输入：项目行、该项目的阶段列表、涉及该项目的冲突对列表（复用 detect_conflicts 结果过滤）、today。
- 输出 HealthScore（pydantic）：total + 五维明细（每维 score / weight / applicable / note / deduction 明细）+ 分档（green/yellow/red）。

五维计算（PHASE8_PLAN §2.2 权重，逐字落地）：
1. **进度达成 35**：机会分 = 35 × (实际进度% ÷ 应达进度%)，封顶 35；应达进度 = (today − plan_start) ÷ (plan_end − plan_start)；未开始或日期缺失 → 该维 applicable=False，标注「无计划基线」。
2. **延期暴露 25**：无延期阶段 25；有延期 max(0, 25 − 延期阶段数×5 − 最长延期天数÷2)。
3. **返工频次 15**：15 − 返工次数×5（下限 0）；返工 = Phase.rework_count > 0 累计。
4. **资源冲突 15**：15 − 参与冲突对数×5（下限 0）；冲突对复用 detect_conflicts（口径与看板/热力图同源）。
5. **计划合理性 10**：工期 ∈ [7,120] 天得 10；<7 或 >120 得 0 并标注「工期异常」；日期缺失 → applicable=False。

分档：总分 ≥80 绿 / 60–79 黄 / <60 红。**缺数据维不计入分母**（总分 = 可算维度得分之和，分母 = 可算维度权重之和），明细显式标注「无计划基线，仅按可算维度计分」——不用 0 冒充。

**搁置项目**：搁置项目健康度列显示「—」（不评），明细弹窗不展示。已完成项目正常评分（快照语义）。

**事实规则（v2 最终态）**：
- 阶段逾期 ≥7 天未完成 → 红「1个阶段逾期X天」/「N个阶段逾期最长X天」（X=最长）。
- 阶段逾期 1–6 天 → 黄。
- 资源冲突 ≥3 对（阶段对去重）→ 黄「资源冲突N对」；1–2 对属常态占用不预警。
- 无阶段 / 活跃阶段均无计划日期 → 灰「未评估」（不冒充绿）。
- 有事实 + 部分活跃阶段无计划日期 → 事实定档，facts 附注「N 个活跃阶段无计划日期，未纳入判定」。
- 无事实 + 存在无计划日期的活跃阶段 → 灰「未评估」（无法判定全貌，不冒充正常）。
- 无以上事实（含全部阶段已完成的项目）→ 绿「正常」。
- 多事实同现只显最严重一条短语（红>黄，同档逾期>冲突）；N = 全部逾期阶段数（含 1–6 天档），X = 最长逾期天数。
- 事实只来自有日期的活跃阶段；完成阶段不产生逾期，冲突对按 detect_conflicts 口径（完成/搁置阶段不参与）。
- 逾期口径复用看板「延期项目」；冲突口径复用 detect_conflicts（均与既有同源）。
- 搁置不评、专项查询层排除（不变）。
