项目管理平台 — 公司内网部署操作指南

适用于闲置机器部署，团队通过内网浏览器访问

一、核心逻辑

你的闲置机器（内网IP 192.168.1.100）
├── Nginx（端口 80）
├── 前端：npm run build 后的静态文件
├── 后端：Gunicorn + FastAPI（端口 8000）
└── SQLite

同事浏览器 → http://192.168.1.100 → 直接打开平台

二、确定闲置机器的系统

机器现系统建议
Ubuntu / Linux✅ 直接部署，最佳选择
Windows 10/11 专业版⚠️ 可以，但要关防火墙 + 装 Nginx for Windows，稳定性较差
macOS 旧机器✅ 可以部署
⚠️ 强烈建议：如果闲置机器是 Windows，花半小时格盘装 Ubuntu Server 22.04（U 盘安装）。作为长期运行的服务，Linux 比 Windows 稳定一万倍。这是你这次部署性价比最高的半小时投入。

三、给机器固定 IP

公司内网一般用 DHCP 自动分配 IP，但服务器必须固定 IP，否则重启后 IP 变了同事就找不到。

方法 A（推荐）：路由器 DHCP 绑定

登陆公司路由器管理后台 → 找到这台机器的 MAC 地址 → 绑定一个固定 IP（如 192.168.1.100）。无需改机器配置。

方法 B：机器上静态 IP 配置

Ubuntu Server 修改 /etc/netplan/00-installer-config.yaml：

network:
  ethernets:
    eth0:
      dhcp4: no
      addresses:
        - 192.168.1.100/24
      routes:
        - to: default
          via: 192.168.1.1          # 你的路由器地址
      nameservers:
        addresses: [114.114.114.114, 8.8.8.8]
  version: 2
sudo netplan apply
💡 选哪个：能进路由器后台就选 A，搞不定就选 B。但要确保选的 IP 不在 DHCP 池范围内（比如路由器 DHCP 分配 192.168.1.2-99，你选 100 以上就安全）。

四、部署步骤

4.1 环境准备

# SSH 连到闲置机器
ssh user@192.168.1.100

# 装依赖
sudo apt update
sudo apt install -y nginx python3.12 python3.12-venv python3-pip git nodejs npm

# 拉代码
cd /opt
git clone git@github.com:ATM-Q797/pm-platform.git
cd pm-platform

4.2 部署前端

cd /opt/pm-platform/frontend
npm install
npm run build           # 产出在 dist/ 目录

# 把 dist/ 交给 Nginx
sudo cp -r dist/* /var/www/html/

4.3 部署后端

cd /opt/pm-platform/backend
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
pip install gunicorn uvicorn

# 初始化数据库
python init_db.py

4.4 配置 Nginx

创建 /etc/nginx/sites-available/pm-platform：

server {
    listen 80 default_server;
    server_name _;

    # 前端静态文件
    location / {
        root /var/www/html;
        index index.html;
        try_files $uri $uri/ /index.html;   # 单页应用必须有这条
    }

    # 后端 API 代理
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
sudo ln -s /etc/nginx/sites-available/pm-platform /etc/nginx/sites-enabled/
sudo nginx -t              # 检查配置
sudo systemctl restart nginx

4.5 systemd 保活后端进程

创建 /etc/systemd/system/pm-platform.service：

[Unit]
Description=PM Platform Backend
After=network.target

[Service]
User=www-data
WorkingDirectory=/opt/pm-platform/backend
ExecStart=/opt/pm-platform/backend/venv/bin/gunicorn -w 2 -k uvicorn.workers.UvicornWorker app.main:app -b 127.0.0.1:8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable pm-platform
sudo systemctl start pm-platform
sudo systemctl status pm-platform   # 看是否 running
✅ 做完这五步，浏览器访问服务器 IP 就能看到平台了。

五、打开防火墙（关键，最容易被忘）

Ubuntu

sudo ufw allow 80/tcp
sudo ufw enable
sudo ufw status

Windows

控制面板 → Windows Defender 防火墙 → 高级设置 → 入站规则 → 新建规则 → 端口 → TCP 80 → 允许。

公司网络如果有企业防火墙

这是唯一可能卡住的点。让 IT 同事放开闲置机器的 80 端口。一般情况下，同网段的机器访问不受企业防火墙限制。

六、同事怎么用

同事操作
打开浏览器输入 http://192.168.1.100
收藏夹加个书签，就不用记 IP 了
手机也能访问连公司 WiFi，同样打开这个地址

不需要装任何软件，有浏览器就行。

七、常见坑

坑排查
同事访问不了① ping 192.168.1.100 看通不通
② 在服务器上 curl localhost:80 看 Nginx 活着没
③ 防火墙端口开了没
过几天 IP 变了没配固定 IP，回去做第三步
重启后服务挂了systemctl enable nginx && systemctl enable pm-platform 设置开机自启
机器休眠了关掉休眠：systemctl mask sleep.target suspend.target hibernate.target
数据库文件越来越大SQLite 会自动管理，但建议定期备份到 U 盘/另一个目录

八、与云部署对比

维度内网闲置机器云服务器
成本0¥50-100/月
访问范围仅公司内网/WiFi全球
稳定性看机器本身（老机器可能不稳）商业级 99.9%
安全性天然隔离外网需要防护
维护IT 不管的话你自己管云平台自动运维
适合阶段MVP 团队试用 🟢正式上线后 🔵
