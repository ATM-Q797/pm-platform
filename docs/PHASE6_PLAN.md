## 二、Phase 6 功能规划

### 6.1 关键路径计算（CPM）

**业务背景**：目前甘特图展示了依赖关系，但没有计算"关键路径"——即决定项目最早完成时间的那条最长路径。项目经理需要知道哪些阶段是"不能延期"的关键节点。

**功能设计**：

| # | 功能点 | 说明 |
|---|--------|------|
| 1 | **关键路径算法** | 基于所有阶段依赖关系（FS/SS/FF/SF），正向计算最早开始/结束（ES/EF），反向计算最晚开始/结束（LS/LF），总时差=0 的阶段即为关键路径 |
| 2 | **甘特图高亮** | 关键路径上的甘特条用**红色粗边框**标记（与返工橙色边框区分），一眼识别瓶颈 |
| 3 | **关键路径开关** | 甘特图工具栏新增「关键路径」切换按钮，默认关闭 |
| 4 | **项目总工期显示** | 项目详情卡显示"关键路径总工期：X 天"，基于 CPM 计算结果 |

**技术方案**：
```
后端：
- 新增 GET /api/projects/{id}/critical-path 端点
- 算法：拓扑排序 → 正向 ES/EF → 反向 LS/LF → 标记 critical=true
- 返回：critical_phase_ids: int[], total_duration: int

前端：
- GanttChart 收到 critical_phase_ids 后，通过 task_class 给对应任务加 gantt-task-critical class
- CSS: .gantt-task-critical { border: 3px solid #ff4d4f; box-shadow: 0 0 6px rgba(255,77,79,0.3); }
- 工具栏 Segmented 新增「关键路径」选项（与日/周/月并列或独立开关）
```

**边界情况**：
- 无依赖的项目：所有阶段都是关键路径（每个阶段自身组成一条路径）
- 多个终点阶段：虚拟终点节点，连接所有无后续的阶段
- SS/FF/SF 非标准依赖：按 dhtmlxGantt 映射规则计算偏移

### 6.2 资源冲突检测

**业务背景**：同一个工程师可能同时被分配到多个时间重叠的阶段。目前资源负载视图只展示"谁在干什么"，不主动提示冲突。

**功能设计**：

| # | 功能点 | 说明 |
|---|--------|------|
| 1 | **冲突检测引擎** | 扫描所有阶段，对每个负责人检查：是否存在两个阶段的计划时间窗口重叠 |
| 2 | **冲突列表** | 新页面或看板卡片：列出所有资源冲突（谁、哪两个项目/阶段、重叠几天） |
| 3 | **甘特图标记** | 资源负载视图中，冲突阶段的甘特条加**黄色警告图标**（⚠） |
| 4 | **冲突详情 hover** | 鼠标悬停冲突条时 tooltip 显示"与「XX 项目·XX 阶段」重叠 N 天" |
| 5 | **首页看板集成** | Dashboard 顶部新增"资源冲突：N 个"卡片，点击跳转冲突详情 |

**技术方案**：
```
后端：
- GET /api/resources/conflicts 端点
- 算法：
  1. 收集所有 assignee_ids → 按人分组
  2. 对每人：取所有 assigned 阶段，检查 plan_start/plan_end 区间是否重叠
  3. 重叠判定：max(start_a, start_b) <= min(end_a, end_b)（有实际重叠天数）
  4. 返回：{ resource_id, resource_name, conflicts: [{ phase_a, phase_b, overlap_days }] }

前端：
- ResourceView 接收 conflicts 数据
- task_class 中检测当前 task 是否在冲突列表中 → 加 gantt-task-conflict class
- CSS: .gantt-task-conflict { border-color: #faad14; } + ⚠ 角标
- Dashboard 新增冲突卡片（见 6.3）
```

**边界情况**：
- 同一工程师在同一项目的多个阶段：不算冲突（视为正常分工）
- plan_start 或 plan_end 为 null：跳过该阶段
- 只在"未开始/进行中/延期"状态检测，已完成/已搁置不检测

### 6.3 首页看板增强 + 延期自动预警

**业务背景**：首页看板目前有基本的统计卡片（项目数、进行中、延期数、阶段数）。需要增强预警能力，让管理者打开首页就能看到风险。

**功能设计**：

| # | 功能点 | 说明 |
|---|--------|------|
| 1 | **延期自动预警** | 定时/页面加载时检查：plan_end < 今天 且 status ≠ 已完成 → 自动标记"延期" |
| 2 | **即将到期预警** | plan_end 在未来 7 天内且 status ≠ 已完成 → 标记"即将到期"，首页黄色卡片 |
| 3 | **首页卡片扩展** | 新增：🔴 延期项目 N、🟡 即将到期 N、⚠️ 资源冲突 N、📊 关键路径总工期 |
| 4 | **预警邮件/通知** | （可选，Phase 6 后期）延期阶段自动通知项目负责人 |
| 5 | **延期趋势图** | 简单的近 4 周延期数量折线图（前端 ECharts 或 antd Charts） |

**技术方案**：
```
后端：
- 扩展现有 GET /api/dashboard/stats 端点
- 新增返回字段：
  - due_soon_count: int（未来 7 天内到期）
  - conflict_count: int（资源冲突数，复用 6.2 检测逻辑）
  - critical_duration: int | null（关键路径总工期，取所有项目中最大）
  - delayed_phases: [{ phase_id, phase_name, project_name, overdue_days }]
  - due_soon_phases: [{ phase_id, phase_name, project_name, days_left }]

- 延期自动标记逻辑：
  已有"延期"状态，但需确保系统能自动检测：
  - 方案 A（推荐）：每天首次访问 Dashboard 时触发检测
  - 方案 B：Cron 定时任务（需配合 APScheduler 或系统 cron）
  - 先实现方案 A，后续可升级为方案 B

前端：
- Dashboard 卡片布局从 4 列扩展为 2 行 × 4 列
- 新增卡片用不同颜色区分：红色（延期）、黄色（即将到期）、蓝色（冲突）
- 点击卡片 → 展开详情列表（Modal 或 Drawer）
```

### 6.4 周报自动生成

**业务背景**：项目经理每周需要汇报项目进展。目前靠人工整理。自动生成一份结构化的周报（Markdown/文本格式），可复制到邮件或飞书/微信。

**功能设计**：

| # | 功能点 | 说明 |
|---|--------|------|
| 1 | **周报生成器** | 选择项目（或全部项目），生成上周至今的进展周报 |
| 2 | **周报内容** | ① 整体进度概览（完成率）② 本周完成阶段 ③ 进行中阶段及进度 ④ 延期/即将到期预警 ⑤ 下周计划 |
| 3 | **导出格式** | 支持 Markdown（默认）、纯文本。Markdown 可直接粘贴到飞书/钉钉 |
| 4 | **一键复制** | 生成后一键复制到剪贴板 |
| 5 | **历史周报** | 保存生成的周报到数据库，可回溯查看（可选，Phase 6 后期） |

**技术方案**：
```
后端：
- POST /api/reports/weekly
- 请求体：{ project_ids?: int[] }（不传 = 全部项目）
- 算法：
  1. 收集指定项目的所有阶段
  2. 按状态分组统计
  3. 筛选本周有进度变化的阶段（通过 operation_log 对比）
  4. 延期检测
  5. 用 Jinja2 模板渲染 Markdown
- 返回：{ markdown: string, plain_text: string, generated_at: string }

前端：
- 导航栏新增「周报」入口（admin/manager 可见）
- 页面布局：
  - 顶部：项目多选 Select +「生成本周周报」按钮
  - 中间：Markdown 预览（用 react-markdown 渲染）
  - 底部：复制 Markdown / 复制纯文本 两个按钮
```

**周报模板示例**：
```markdown
# 智能终端研发周报
> 2026-08-04 ~ 2026-08-10 | 共 18 个项目

## 📊 整体进度
- 阶段总数：57 | 已完成：12（21%） | 进行中：30 | 未开始：10 | 延期：5

## ⚠️ 风险预警
- 🔴 延期阶段：5 个
  - 终端A · P5结构设计（延期 3 天）
  - 终端B · P7联调测试（延期 7 天）
- 🟡 即将到期：3 个

## ✅ 本周完成
- 终端A · P3模块选型 → 已完成
- 终端C · P1需求评估 → 已完成

## 🔄 进行中
- 终端B · P6样机打样：进度 60%
- 终端D · P4工业设计：进度 30%

## 📅 下周计划
- 终端A · P4工业设计（计划开始 08-12）
- 终端B · P7联调测试（计划结束 08-15）
```

## 六、风险与对策

| 风险 | 对策 |
|------|------|
| CPM 算法处理复杂依赖（SS/FF/SF） | 先支持 FS（占 90% 场景），复杂类型按 FS 近似计算 |
| 资源冲突误报（同一项目多阶段） | 加项目归属判断，同一项目不算冲突 |
| 延期自动标记与手动状态冲突 | 自动标记只影响"未开始/进行中→延期"，不覆盖已完成/已搁置 |
| 周报生成性能（18 项目遍历） | 后端计算，18 项目数据量小，无需异步 |
