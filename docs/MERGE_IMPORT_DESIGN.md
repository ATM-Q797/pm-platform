# 合并导入设计方案（增量合并 + 差异项合并）

> **版本**: v1.0 | **日期**: 2026-08-18
> **状态**: 设计待确认
> **背景**: 原导入为"全量重置"（导入=清空现有+写入文件），需改为"增量合并"

---

## 一、需求（优化后的表述）

### 1.1 用户需求原文

> 导入数据的操作是增项导入和差异项合并，不存在的数据不做改动，而不是我导入的数据如无系统数据时删除。

### 1.2 需求拆解

| # | 规则 | 说明 |
|---|------|------|
| R1 | **增项导入** | 文件中存在、系统中不存在的项目 → 新增 |
| R2 | **差异项合并** | 文件中存在、系统中也存在（同名）的项目 → 按文件数据合并更新 |
| R3 | **保留不动** | 系统中存在、文件中不存在的项目 → **保留，不做任何改动**（不再删除） |
| R4 | **取消全量删除** | 任何情况下不因导入删除系统已有数据（项目/阶段/资源） |
| R5 | **合并报告** | 导入后/预览时明确告知：新增了哪些、更新了哪些、保留了哪些 |

### 1.3 用户故事

- 作为管理员，我导入一份"本周更新"的 Excel，系统应**只新增文件里的新项目**、**更新同名项目**、**保留其他项目**，而不是清空重来
- 作为管理员，我在导入前应看到**合并差异预览**：哪些会新增、哪些会更新、哪些保持不变
- 作为管理员，我不小心导入了旧文件/部分文件时，系统**不会删除**任何现有数据

## 二、合并逻辑分析

### 2.1 匹配键

| 实体 | 匹配键 | 理由 | 风险 |
|------|--------|------|------|
| **项目** | `name`（项目名称） | 项目编号是系统自动生成（连续整数），导入时重编，无法作为稳定键 | 项目改名会被当作"新项目"新增（原项目保留）→ 报告提示 |
| **阶段** | `phase_type`（P1-P8，项目内唯一时） | 阶段类型是标准字典（需求评估~交付），语义稳定 | 同一项目内多个相同类型阶段（罕见）→ 按顺序匹配，多余的新增 |

> 备选匹配键（不推荐）：项目 code 不稳定；阶段 name 可被用户改名（P4 改名后不匹配）。

### 2.2 项目合并规则（同名项目）

按**字段粒度**：文件有值（非空）→ 覆盖；文件为空 → 保留系统现值。

| 字段 | 文件值 | 系统值 | 结果 |
|------|--------|--------|------|
| 类目 / 市场 / 负责人 / 计划起止 / 备注 | 有值 | 任意 | **覆盖为文件值** |
| 类目 / 市场 / 负责人 / 计划起止 / 备注 | 空 | 有值 | 保留系统值 |
| **状态** | 有值 | 任意 | **覆盖为文件值**（用户确认：文件状态/进度需同步系统） |
| **进度** | 显式填写（0-100） | 任意 | 覆盖为文件值 |
| **进度** | 未填 | 有值 | 保留系统值（按状态推断值不覆盖） |

### 2.3 阶段合并规则（同名项目内）

| 场景 | 规则 |
|------|------|
| 文件的阶段类型（P1-P8）在系统中**存在** | **更新**：日期（计划/实际）、状态、进度、负责人、备注——文件有值覆盖，空保留 |
| 文件的阶段类型在系统中**不存在** | **新增**：追加到项目末尾（sequence = 项目最大序号 + 1） |
| 系统中存在、文件未包含的阶段 | **保留不动**（不做删除、不改动） |
| 文件阶段进度 | 显式填写的 0-100 覆盖；未填 → 按状态推断（与现逻辑一致） |

### 2.4 依赖与资源

| 项 | 规则 |
|----|------|
| **已有依赖** | **完全不动**（保留用户手动建立的 FS/SS/FF/SF 与跨阶段依赖） |
| **全新项目**的依赖 | 按 sequence 建 FS 串联链（与现逻辑一致：项目内全新建，序号=顺序成立） |
| **同名项目新增阶段**的依赖 | **不自动建**（避免 P7→新P1 颠倒依赖；甘特图手动连线，一次拖拽） |
| 新增阶段的插入位置 | 按阶段类型自然顺序**插入**（P1 插最前、P8 插最后，后续序号顺延），甘特图保持 P1→P8 阅读顺序 |
| **资源（人员）** | 只增不删：文件中出现的新人员 → 新增 resource；现有人员保留 |

### 2.5 边界情况

| 情况 | 处理 |
|------|------|
| 文件为空/无可识别 sheet | 报错，不执行任何合并 |
| 同名项目但市场/类目变化大 | 按文件覆盖（R2 语义）；报告中标出"字段更新"明细 |
| 项目中无日期阶段 | 保留系统值（空不覆盖） |
| 项目名相同、但阶段类型全部不同 | 全部阶段新增，项目字段更新 |
| 重复导入同一文件 | 幂等：第二次导入时同名项目更新为相同值，无重复新增 |

### 2.6 合并报告（预览与结果）

```
合并预览报告：
📥 新增项目：2 个
    - XX银行自助终端TCM-001（拉美区，3 阶段）
📝 更新项目：5 个
    - 工行自提穿墙主柜（类目/计划结束/新增 1 阶段）
🔒 保留项目：10 个（文件中未包含，不做改动）
阶段：新增 3 / 更新 8 / 保留 43
```

## 四、技术方案

### 4.1 后端

```python
# excel_importer.py 新增
def import_merged(db, parsed: ParsedWorkbook) -> ImportReport:
    """增量合并导入（默认模式）：
    - 同名项目 → 字段级合并更新
    - 新项目 → 创建
    - 阶段按 phase_type 匹配更新/新增
    - 不删除任何现有数据
    """
    for p in parsed.projects:
        existing = db.scalars(select(Project).where(Project.name == p.name)).first()
        if existing:
            _merge_project(db, existing, p)      # 字段级覆盖 + 阶段合并
        else:
            _create_project_with_phases(db, p)   # 与现逻辑相同
    db.commit()

# 报告扩展：ImportReport 增加 merged/created/kept 统计
```

- `_merge_project`：项目字段非空覆盖；阶段按 phase_type 匹配（`{phase_type: phase}` 映射），更新或追加
- 阶段更新 = 文件非空字段覆盖（plan_start/plan_end/actual_start/actual_end/status/progress/remark/assignees）
- assignees（负责人）合并：文件有 → 覆盖负责人列表；文件空 → 保留

### 4.2 前端

- 确认 Modal：`📥 新增 N / 📝 更新 M / 🔒 保留 K` 三段展示 + 项目明细
- 确认按钮文案：「确认合并导入」（绿色/蓝色，不再是危险色）
- 结果报告同步展示三段统计

### 4.3 API

```
POST /api/import/preview   # 返回合并预览（新增/更新/保留明细）
POST /api/import/excel     # 执行合并导入（默认）；?mode=replace 保留全量重置能力
```
