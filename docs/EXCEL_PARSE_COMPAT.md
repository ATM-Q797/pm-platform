## 一、问题根因（实测确认）

| # | 问题 | 影响 | 根因 |
|---|------|------|------|
| 1 | 阶段行编号用点分 `1.1`（模板要求连字符 `1-1`） | 50 行丢失 | `classify_row` 的 `_PHASE_CODE_RE` 只认 `^\d+-\d+$`，`1.1` 不匹配 → skip（静默） |
| 2 | 阶段行不填编号（仅阶段类型/日期/进度） | 114 行丢失 | 编号+名称全空 → `classify_row` 返回 skip |
| 3 | 日期点分 `2026.6.29` | 16 条警告 | `parse_cell_date` 不支持 `%Y.%m.%d` |
| 4 | 无法识别的行静默跳过 | 用户无感知丢数据 | skip 不产生任何报告 |

**核心认知（用户决策）**：阶段行的判定**应以阶段类型列为主**，而非编号；编号仅作行归类与排序辅助。

## 二、改造方案（只改解析层，模板 14 列结构不动）

### 2.1 行判定重构（classify_row）

新判定优先级（**评审处置 #1：阶段类型优先于项目判定**）：

```
① 阶段类型列可解析（P1-P8 前缀
   或阶段名映射表命中）               → 阶段行 ★核心
   （不依赖编号；编号格式任意）
② 编号为纯数字 且 名称非空           → 项目行（更新 current_project）
   （此时阶段类型列必然为空或不可解析，否则 ① 已命中）
③ 编号匹配 ^\d+-\d+$ 或 ^\d+\.\d+$   → 阶段行（兼容新旧两种编号格式）
④ 有内容但以上均不匹配               → 跳过 + 警告「第X行无法识别（…）」
```

> 说明：阶段行即使编号为纯数字（如填了 `1` 而非 `1-1`），只要阶段类型可解析即判为阶段行（评审处置 #1）。

### 2.2 阶段行归属规则（current_project 跟踪）

| 阶段行编号情况 | 归属 |
|---|---|
| `1-1` / `1.1`（父号 = 前段数字） | 父号 == current_project 编号 → 直接归属；不一致 → 警告 + 归属 current_project |
| 无编号 | 归属 current_project（用户表格的实际语义：项目行下挂阶段行） |
| 无编号 且 无 current_project（文件开头即阶段行） | **错误**「阶段'…'缺少父项目」+ 跳过（评审处置 #7：归入报告 errors[] 桶，非警告） |

### 2.3 通用清洗层 `clean_cell()`（复制粘贴兼容）

应用于**所有文本列**（编号/名称/负责人/市场/阶段类型/日期/状态/进度/备注）：

1. 全角 → 半角（NFKC：`１→1`、`２０２６→2026`、`Ａ→A`、`（→(`、`．→.`、`％→%`）
2. 去首尾空白（含全角空格 `\u3000`）
3. 去不可见字符（零宽 `\u200b-\u200f`、`\ufeff`、`\u00a0`、`\u2000-\u200a`）
4. 压缩连续空白（`"P1  需求评估"` → `"P1 需求评估"`）

### 2.4 日期多格式解析链（parse_cell_date 扩展）

```
数值单元格（int/float，未经 clean_cell）：
0. 评审处置 #5 补全——先按 7/8 位 YYYYMMDD/YYYYMDD 解析（用户在 Excel 输入 20260629
   常被存为数字而非文本）；月/日非法（20261399）才落到序列号判定。与文本链同序：
   若序列号优先，区间内 7 位日期（2026629 < 2_958_465）会被误当序列号解析成 7447 年。
   7 位但非合法日期（如 1000000 → 1000-00-00 月 0）仍按范围内序列号解析，序列号语义不变。

clean_cell 后依次尝试：
1. Excel 序列号（数值/数字文本）——仅当数值在有效范围（1..2_958_465，对应 1900-9999）内才按序列号解析，越界则落到后续格式（评审处置 #5）
2. %Y-%m-%d / %Y/%m/%d / %Y.%m.%d   （月日允许 1-2 位）
3. %Y年%m月%d日
4. 纯数字 8 位 %Y%m%d / 7 位 %Y%m%d（20260629 / 2026629）
5. 短格式 %m-%d / %m/%d / %m.%d     → 按当年解析 + 警告「日期缺少年份，按2026年解析」（决策 A）
失败 → 警告（现有行为）
```

### 2.5 进度解析统一

`50%` / `50％` / `50 %` / `0.5` / `50` → **统一为 0-100 数值**（50%→50、0.5→50、50→50）；无法解析 → 警告 + 置空。
> 评审处置 #3：解析输出统一 **0-100**（与 DB 列 `progress INTEGER 0-100`、合并导入规则一致）；gantt API 层的 0-1 转换由现有 API 层负责，本改造不动。

### 2.6 阶段类型解析增强（parse_phase_type_cell）

- 清洗后：`P1 需求评估` / `P1需求评估` / `P１ 需求评估`（全角 P 经 NFKC）→ `(P1, 需求评估)`
- 纯 `P1` → name 用默认前缀（现有）
- 无 P 前缀 → `PHASE_NAME_TO_TYPE` 映射表（**评审处置 #4：比较前对映射表键做同样的 NFKC 归一化**——表内「样机打样（1台）」等全角括号键与清洗后的半角输入可匹配）
- 均失败 → 返回 None，上层**警告 + 跳过该行**（决策 2：不猜、不吞）

### 2.7 跳过可见化（④）

所有 skip 行（除全空行）一律追加警告：
- 无法识别：`第X行无法识别（编号='1.1' 阶段类型='…'），已跳过`
- 缺父项目：`阶段'…'缺少父项目，已跳过`
